# Decisions

## Rules

- **Strip by gutting, not by deleting call sites.** When removing an upstream subsystem, replace its internals and keep its API and callers, so upstream `dev` merges stay mechanical. This rules out deleting `ext.telemetry` usages across the codebase.
- **No marketing notifications.** The extension never raises a pop-up that markets anything (surveys, newsletters, sign-ups). Links may sit in an existing webview. This rules out reintroducing upstream nag prompts on merge.
- **Ids come from the rebrand script.** Every public id renamed from upstream (`kdb.*` → `peachq.*`, views, the notebook type, product titles) is produced by `tools/rebrand.mjs`, and upstream enters through it (`docs/developer/upstream.md`).
  - This rules out hand-editing a `kdb.*` id into `peachq.*`, and merging KX `dev` without first running the script on it.
  - Why: both sides then spell every id the same way, so merges conflict only where real code changed, and `--check` plus the rebrand test catch drift.
- **Defer to an active KX extension.** Only one of the two is ever active in a window. While `KX.kdb` is enabled (and `peachq.deferToKx` is `auto`), peachq starts no language client and its keybindings are off.
  - This rules out running both at once and silently overriding KX.
  - Why: both claim language `q`, the same files and the same shortcuts, and duplicate language servers and bindings give the user conflicting results.
- **CI never touches KX.** No KX q, image, registry, token or licence in any workflow. The only q in CI is a pinned, checksummed peachq (`.peachq-version` through `peachq-org/setup-peachq`, pinned by SHA). This rules out reviving the qcumber/qpbuild job or any KX secret, because the project must build and test with nothing anyone needs a KX licence for.
- **q code is tested with qunit on peachq.** The q the extension injects is tested by `test/q/qunit/*Test.q` through `test/q/run.q`, which refuses non-peachq q and exits non-zero on failure. When peachq diverges from documented kdb, the test stays as a `skip*` with a reason and a NOTES-FOR-PEACHQ line. The expectation is never bent. This rules out editing an expected value to make peachq pass, because the expectations are kdb's contract with end users, who may run KX q.
- **Manual testing is peachq-only and headless for agents.** `qserver.ts` starts only a q that answers `.pq.version`, and agents run the driver with `HEADLESS=1` and `DISPLAY`/`WAYLAND_DISPLAY` unset, never `--headed`; a human may pass it. This rules out pointing the tool at KX q and agents opening windows on a developer's display. Why: rule zero, and agent runs must not take over the owner's screen.
- **Bundled peachq never displaces the user's q.** The bundled binary is the last q-resolution candidate (after `qHomeDirectoryWorkspace`, `QHOME`, `qHomeDirectory`, `~/.kx/bin/q`, `PATH`), and the built-in connection is separate from user connections: it is never persisted, exported, edited or removed. This rules out preferring the bundled q or writing it into user settings, because users of KX q must keep the q they chose.
- **Bundled binaries are pinned and checksummed.** A packaged peachq comes only from the `peachq-org/peachq` release named by `.peachq-version`, verified against that release's `.sha256` at build time, and a mismatch fails the build. This rules out unpinned "latest" downloads and runtime downloads, because the vsix must be reproducible and work air-gapped.
- **REPL fixes must hold for kdb as documented.** A change to how the REPL drives q (flags, handler, parsing) is made only when qdocs shows the same code is correct for KX q. Where peachq differs, the row is skipped with a NOTES-FOR-PEACHQ line. This rules out output filters or flags that exist only to hide peachq behaviour, because the REPL must keep working for users on KX q, and a peachq-only path would hide peachq defects.
- **Typed q values are rendered client-side to match q's own text; peachq -classic is the oracle, qdocs wins where they disagree.** Rendering lives in `src/q/text.ts` and is checked row by row against `test/fixtures/q-render/expected.tsv`, which CI regenerates with the pinned peachq. This rules out hand-written expectations and TS approximations of `.Q.s`. A peachq divergence goes in `qdocs.tsv` with its qdocs page and a NOTES-FOR-PEACHQ line. The grid, naked-mode console and copy/export must show what users of KX q see, and a peachq upgrade that changes a text must show up as a CI diff.
- **Every result renders everywhere it can; the console is the full log, the grid adds to it.** A run's text always goes to the console; tables, dictionaries and keyed tables also go to the grid, which updates without taking focus or the panel. This rules out a destination switch or any path where the grid replaces the console, because the console is the record of what ran and the grid only adds a view of it.
- **We send qStudio's wrapper byte for byte and KX's lambda unmodified; anything else is the user's explicit override.** The default run sends the `.vscode` API when the process has it, else `QueryManager.java:276–278` with the 10 MB cap, and `vscode-wrap` sends upstream's lambda as shipped; `naked` sends only the user's text. This rules out editing either wrapper (to add a namespace, say) or sending a third variant, because sites detect the qStudio text and the KX lambda must stay what KX users send.
- **Typed replies are decoded from the raw bytes, not from node-q's values.** qStudio-wrapped and naked replies go through `src/q/decode.ts` from the codec tap; node-q's lossy decode is used only for the extension's own JSON and housekeeping calls. This rules out rendering the grid or console from node-q's JS values, because they lose q types.
- **Whole-file runs use upstream's lambda unmodified; we document how it differs from `\l` rather than change it.** The whole-file command sends the `.vscode` API or KX's lambda as shipped, whatever the query mode, except `naked`. Its differences from `\l` are pinned by `npm run test:l-diff` (`test/fixtures/l-diff/expected.tsv`) and listed in the reference card. This rules out patching `evaluateQ.q`/`formatQ.q` to close a gap such as the exit `\` after a block comment, because the lambda must stay what KX users send, and a CI diff must show when upstream or peachq changes the behaviour.
